# Изменение протокола

Источник истины — Pydantic-модели в `server/app/protocol.py`. Из них генерируется `protocol/schema.json`, а из схемы — `client/src/protocol.gen.ts`. Сгенерированные файлы руками не правятся, хук проекта блокирует такие правки.

## 1. Проверь, что изменение допустимо

- Сервер не читает `data` в `signal` и пересылает его только внутри комнаты отправителя. Новое поле внутри `data` — дело клиента, сервер и модели его не разбирают.
- В сообщениях сервера нет IP-адресов, SDP и кандидатов вне пересылаемого `signal`.
- Сообщение укладывается в 64 КБ.
- Если меняется смысл существующего сообщения, это изменение дизайна: согласуй его с человеком.

## 2. Модель и тесты сервера

1. Сначала тесты: корректный JSON в camelCase разбирается, некорректный даёт `bad-request`, сериализация идёт по алиасам (`by_alias=True`).
2. Модель — класс на сообщение с полем `type: Literal["..."]` и общей конфигурацией `alias_generator=to_camel`, `populate_by_name=True`, как у соседних моделей.
3. Добавь модель в дискриминированное объединение своего направления (клиент → сервер или сервер → клиент) с `Field(discriminator="type")`.
4. Обработчик на сервере и его тесты.

## 3. Генерация

```
npm run gen:protocol
```

`protocol/schema.json` и `client/src/protocol.gen.ts` коммитятся вместе с моделью, в одном коммите. Проверка CI запускает генератор и ждёт пустой `git diff --exit-code`.

## 4. Клиент

- Сообщения сервера разбираются zod-схемой из сгенерированного файла, разбор по `type` исчерпывающий: новое сообщение без обработчика должно ломать `npm run typecheck`.
- Сообщения клиента собираются через сгенерированные типы.

## 5. Совместимость

Клиенты обновляются автоматически, но не одновременно. Новое поле в сообщении клиента делай необязательным, пока старые версии ещё в ходу. Новое сообщение сервера старый клиент не знает: проверь, что он его пропустит, а не упадёт.

## 6. Документация

Обнови список сообщений в разделе «Протокол сигналинга» CLAUDE.md и таблицу протокола в дизайн-документе. Субагент дизайн-документ не правит: он пишет в отчёте, что поменять, а правит основная сессия.

## 7. Проверка

Скилл `verify`: серверные проверки, клиентские проверки и актуальность сгенерированных файлов.
