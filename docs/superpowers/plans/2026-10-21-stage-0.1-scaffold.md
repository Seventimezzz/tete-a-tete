# Этап 0.1. Каркас репозитория — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать проект uv в `server/` и npm workspaces `client` и `site` с инструментами так, чтобы команды проверки из CLAUDE.md работали и ловили ошибки.

**Architecture:** Сервер — приложение uv без сборки пакета, вся конфигурация инструментов в `server/pyproject.toml`. JavaScript-часть — корневой `package.json` с workspaces. Общие инструменты стоят в корне, у каждого workspace свои `tsconfig.json`, `vitest.config.ts` и скрипты `typecheck` и `test`. Корневые `npm test` и `npm run typecheck` вызывают скрипты всех workspaces, `npm run lint` проверяет весь репозиторий из корня.

**Tech Stack:** Python 3.13, uv, FastAPI, uvicorn[standard], Pydantic v2, ruff, mypy, pytest, pytest-asyncio, httpx; Node ≥ 24.15, npm workspaces, TypeScript 6.0, ESLint 10 + typescript-eslint 8, Prettier 3, vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-21-stage-0.1-scaffold-design.md`

## Global Constraints

Из CLAUDE.md, дословно:

- «**Бэкенд — Python и FastAPI**, один процесс uvicorn.»
- «**Сервер:** Python 3.13, FastAPI, uvicorn[standard], Pydantic v2, asyncio (STUN на `DatagramProtocol`), `maxminddb`. Инструменты: uv, ruff, mypy (strict), pytest, pytest-asyncio.»
- «**Клиент:** TypeScript (strict), Electron, Angular (standalone-компоненты, signals, без zone.js), Angular CLI для страницы, esbuild для main и preload, electron-builder (NSIS), electron-updater, zod, vitest.»
- «**Сайт:** статическая страница `/r/<id>` и страница загрузки на TypeScript. Клиент и сайт — npm workspaces.»
- «Время берётся из подменяемых часов, чтобы таймауты тестировались без ожидания.»
- «Не логировать и не хранить IP, SDP и ICE-кандидаты — даже в сообщениях об ошибках.»
- «**Сервер, из `server/`:** `uv run uvicorn app.main:app --reload`, `uv run pytest`, `uv run ruff check`, `uv run ruff format`, `uv run mypy`.»
- «**Клиент и сайт, из корня:** `npm run dev:client` (`ng serve` и Electron вместе), `npm test`, `npm run lint`, `npm run typecheck`.» — `dev:client` появится в 4.1, остальные три — в этом плане.
- Имена: «пакеты, образы и репозиторий — `tete-a-tete`».

Из спецификации:

- TypeScript `~6.0.3`: Angular 22 требует `>=6.0 <6.1`, typescript-eslint 8.72 — `<6.1.0`. TypeScript 7 не ставить.
- Node `>=24.15` (`engines`), `.nvmrc` = `24`.
- Python `>=3.13,<3.14`, `server/.python-version` = `3.13`.
- Не добавлять сейчас: Electron, Angular, esbuild, zod, `maxminddb`, `websockets`, lifespan, эндпоинт `/ws`.

Константы из таблицы CLAUDE.md к 0.1 не относятся.

## Review Focus

1. **Переводы строк на Windows.** У разработчика `core.autocrlf=true`, CI будет на Linux. Ожидается: после свежего checkout все текстовые файлы в рабочей копии с LF, и `prettier --check` проходит одинаково на обеих ОС. Проверяется в задаче 2, шаг 2.
2. **Виртуальное окружение и сборки внутри дерева.** `server/.venv` содержит тысячи файлов, среди них `.js` и `.json`. Ожидается: `npm run lint` их не читает и не падает. Проверяется в задаче 2, шаг 9: lint запускается, когда `server/.venv` уже есть.
3. **Падение одного workspace.** Ожидается: если падает тест или typecheck в `site`, корневые `npm test` и `npm run typecheck` возвращают ненулевой код. Проверяется в задаче 3, шаг 6.
4. **Системный Python 3.12.** На машине по умолчанию `python` — 3.12.4. Ожидается: `uv run` использует 3.13. Проверяется в задаче 1, шаг 2.
5. **Инструменты, которые ничего не ловят.** Ошибки в конфигурации (типовые правила ESLint без `projectService`, banned-api ruff без эффекта) молча выключают проверки. Ожидается: каждая проверка падает на заведомо плохом коде. Проверяется пробами в задаче 1, шаг 8, и задаче 2, шаг 10.
