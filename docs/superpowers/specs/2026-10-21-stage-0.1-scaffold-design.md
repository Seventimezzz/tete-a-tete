# Этап 0.1. Каркас репозитория: сервер и npm workspaces

Дата: 2026-10-21. Пункт плана из CLAUDE.md:

> 0.1 Сервер: проект uv в `server/` (Python 3.13, FastAPI, uvicorn[standard], Pydantic v2), ruff, mypy strict, pytest. Клиент и сайт: npm workspaces `client` и `site`, TypeScript strict, ESLint, Prettier, vitest.

«Готово, когда» этапа 0 (для 0.1 — его часть): `uv run pytest` и `npm test` проходят.

> **Изменено после исполнения.** Workspace `site` удалён: веб-сайта у проекта не будет, только клиент Electron для Windows. Сервер раздаёт лишь установщик и файлы обновлений. Ниже `site` упоминается как история этапа.

## Зачем

Все следующие пункты пишут код и тесты, а агенты проверяют работу командами из CLAUDE.md. Пока команд нет, проверять нечего. 0.1 создаёт проекты и инструменты так, чтобы эти команды работали и ловили ошибки:

- из `server/`: `uv run uvicorn app.main:app --reload`, `uv run pytest`, `uv run ruff check`, `uv run ruff format`, `uv run mypy`;
- из корня: `npm test`, `npm run lint`, `npm run typecheck`.

## Цели

1. `server/` — проект uv: Python 3.13, FastAPI, uvicorn[standard], Pydantic v2. Пакет приложения — `app`, точка входа — `app.main:app`.
2. ruff (линтер и форматтер), mypy в режиме strict, pytest с pytest-asyncio.
3. Корень — npm workspaces с пакетом `client` (изначально и `site`, удалён), общие TypeScript strict, ESLint, Prettier, vitest.
4. Все команды выше проходят на чистом клоне после `uv sync` и `npm ci`.
5. В каждой части есть хотя бы один тест, иначе «тесты проходят» ничего не значит.

## Не цели

- Модели протокола и генератор id комнаты — 0.2.
- `protocol/schema.json`, `protocol.gen.ts`, скрипт `gen:protocol` — 0.3.
- CI — 0.4.
- Electron, esbuild, Angular CLI, `app://`, `npm run dev:client` — 4.1. В `client/` пока нет ни Electron, ни Angular.
- WebSocket `/ws`, lifespan, часы, комнаты — этап 1. `maxminddb` — этап 6.
- Dockerfile — 3.2.

Найдено при подготовке:

- **TypeScript закрепляется на 6.0.x.** Angular 22 (`@angular/build`, `@angular/compiler-cli` 22.2) требует `typescript >=6.0 <6.1`, typescript-eslint 8.72 — `<6.1.0`. Последний TypeScript — 7.0, его ставить нельзя: на 4.1 пришлось бы откатывать. Версии проверены `npm view` 2026-10-21: typescript 6.0.3, eslint 10.13, typescript-eslint 8.72, prettier 3.9, vitest 5.0, Angular 22.2.
- **Node ≥ 24.15.** Столько требует `@angular/build` 22; vitest 5 — `^22.12 || ^24 || >=26`. На машине разработчика Node 24.18.
- **Переводы строк.** У разработчика `core.autocrlf=true`, CI будет на Linux. Без `.gitattributes` Prettier с `endOfLine: lf` по-разному отработает локально и в CI.
- **README.md в UTF-16 LE с BOM.** Остальные файлы в UTF-8.

## Как устроено

### Сервер

- `server/pyproject.toml`: имя `tete-a-tete-server`, `requires-python = ">=3.13,<3.14"`, `server/.python-version` = `3.13`. Зависимости: `fastapi`, `uvicorn[standard]`, `pydantic>=2`. Группа `dev`: `ruff`, `mypy`, `pytest`, `pytest-asyncio`, `httpx` (для тестов через ASGI). `uv.lock` в git.
- Проект — приложение, а не библиотека: пакет `app` не устанавливается, тесты видят его через `pythonpath`.
- `app/main.py`: `app = FastAPI(docs_url=None, redoc_url=None, openapi_url=None)`. HTTP-API у сервиса нет, Caddy проксирует только `/ws` *(наше решение)*.
- ruff: `target-version = "py313"`. Набор правил — на усмотрение исполнителя, но в него входят *(наше решение)*:
  - `T20` — запрет `print`: вывод только через logging, где его видно на ревью приватности;
  - `S` (bandit), `ASYNC` — блокирующие вызовы в async-коде;
  - `TID251` banned-api для `app/`: `time.time`, `time.time_ns`, `time.monotonic`, `time.monotonic_ns`, `time.perf_counter`, `time.perf_counter_ns`, `datetime.datetime.now`, `datetime.datetime.utcnow`, `datetime.datetime.today`, `datetime.date.today` — правило подменяемых часов. `loop.time()` так не запретить, его ловит ревью. Будущий модуль часов получит исключение в `per-file-ignores`, тесты не ограничиваются.
- mypy: `strict = true`, плагин `pydantic.mypy`, проверяются `app` и `tests`.
- pytest: `asyncio_mode = "auto"`, `xfail_strict = true` (на нём держатся пометки находок QA), `--strict-markers`, `--strict-config`, `filterwarnings = ["error"]`.
- Тесты-заготовки: `/docs`, `/redoc` и `/openapi.json` отвечают 404. Тесты асинхронные, через `httpx.AsyncClient` + `ASGITransport`, без маркера — так заодно проверяется `asyncio_mode = "auto"`. `starlette.testclient.TestClient` не используется: Starlette 1.9 с `httpx` выдаёт предупреждение об устаревании и требует пакет `httpx2`, а новый пакет без согласования не добавляем.

### Клиент и сайт

- Корневой `package.json`: имя `tete-a-tete`, `private`, `"type": "module"`, `workspaces: ["client", "site"]`, `engines.node: ">=24.15"`. Общие инструменты — в devDependencies корня: `typescript ~6.0.3`, `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-config-prettier`, `prettier`, `vitest`, `@types/node`, `globals`. `package-lock.json` в git. `.nvmrc` = `24`.
- Скрипты корня: `lint` = ESLint по всему репозиторию + `prettier --check`; `format` = `prettier --write`; `typecheck` и `test` запускают одноимённые скрипты всех workspaces.
- Workspaces `@tete-a-tete/client` и `@tete-a-tete/site` *(имена — наше решение)*: свои `tsconfig.json`, `vitest.config.ts`, скрипты `typecheck` (`tsc --noEmit`) и `test` (`vitest run`).
- `tsconfig.base.json` в корне: `strict` и флаги, которые Angular CLI включает по умолчанию (`noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`), плюс `noUncheckedIndexedAccess`, `isolatedModules`, `verbatimModuleSyntax`; `moduleResolution: "bundler"` — так собирают и esbuild, и Angular; `target` ES2022, `lib` ES2023 без DOM. DOM-типы и окружение тестов `jsdom` workspaces добавят, когда появится код для страницы (4.1, 10.3); заготовки тестируются в окружении `node` *(наше решение)*. `exactOptionalPropertyTypes` не включаем: он плохо сочетается со сгенерированными zod-типами *(наше решение)*.
- ESLint — flat config в корне: `@eslint/js` recommended, `typescript-eslint` strictTypeChecked и stylisticTypeChecked с `projectService`, `eslint-config-prettier` последним. Файлы `*.js`, `*.mjs`, `*.cjs` проверяются без типов, `*.cjs` — как CommonJS. `server/`, `.claude/`, `docs/`, `.superpowers/`, кэш Angular `.angular/`, сборки и покрытие не проверяются. Каждый `*.ts` должен входить в `include` какого-нибудь tsconfig, иначе ESLint падает с «not found by the project service».
- Prettier: `singleQuote`, `printWidth: 100` (стиль Angular). Markdown Prettier не форматирует: CLAUDE.md, спецификации и планы пишутся вручную, и переформатирование таблиц засорило бы их историю *(наше решение)*.
- В каждом workspace — минимальный модуль в `src/` и тест к нему. Тесты-заготовки заменяются настоящими в 0.3 и 4.1.

### Общие файлы репозитория

- `.gitattributes`: `* text=auto eol=lf`; `*.cmd`, `*.bat`, `*.ps1` — `eol=crlf`; бинарные форматы — `binary`.
- `.editorconfig`: UTF-8, LF, перевод строки в конце, 2 пробела; 4 пробела для `*.py`.
- `.gitignore`: дополнить `node_modules/`, `dist/`, `out/`, `coverage/`, `.venv/`, `__pycache__/`, кэши ruff, mypy и pytest, `*.egg-info/`, `.env` и `.env.*` (кроме `.env.example`).
- README.md перекодировать в UTF-8 с LF, текст не менять.

## Что остаётся исполнителю

Точный набор правил ruff сверх перечисленных, длина строки Python, содержимое модулей-заготовок, раскладка конфигов ESLint для `*.js` и `*.config.ts` вне `src/`.

## Как проверить

На чистом клоне:

1. `cd server && uv sync && uv run ruff check && uv run ruff format --check && uv run mypy && uv run pytest` — всё проходит, тестов ≥ 2.
2. `uv run uvicorn app.main:app` стартует, `GET /docs` → 404.
3. Из корня: `npm ci && npm run lint && npm run typecheck && npm test` — всё проходит, тесты есть в обоих workspaces.
4. Инструменты ловят ошибки: `print()` или `time.time()` в `app/` → `ruff check` падает; функция без аннотаций → `mypy` падает; неиспользуемая переменная в `client/src` → `npm run lint` падает; присваивание `string` в `number` → `npm run typecheck` падает. Проверяется вручную, в репозиторий не коммитится.
5. `npm ls typescript` показывает 6.0.x.
